# AgentReaper

AI コーディングエージェントが残した子プロセスを回収する、Windows のタスクトレイ常駐ツール。

[English README](README.md) · [AGENTS.md](AGENTS.md)

---

## 何が起きているか

Claude Code / Codex / Cursor を一日中動かしていると、MCP サーバーやフックスクリプトが
絶えず起動される。ほとんどは正常に終了する。しないものがある。セッションが異常終了すると、
その子プロセスは親を失って residual として残り、CPU は使わないまま
メモリとハンドルを握り続ける。

作者の環境での実測:

- 停止したフックプロセス 55 件。全件が孤児で、**全件 CPU 0 秒**。
  最古は **6.5 日**（9,318 分）生存。合計約 **2.6GB**
- 1 つのエージェントクライアント配下に孤児の MCP サーバー 23 件。21 時間気づかなかった

CPU 使用率には出ない。一週間かけてじわじわ重くなる形と、
実空きページが静かに減っていく形で出る。

## 何をするか

「孤児・CPU 無活動・一定時間経過・複数個」という形だけを探して、
プロセスツリー単位で終了させる。前後の変化を出す。

あわせてメモリリストの状態を読む。体感する症状（マウスが一瞬止まる）と相関するのは、
タスクマネージャーが「利用可能」と呼んでいる数値ではなく、実空き（ゼロ化済み）ページのほう。

**汎用の PC 高速化ツールではない。** 1 つの故障モードだけを対象にしている。

## これは「ガワ」

このリポジトリは **仕組みだけで、設定が入っていない。**
clone した時点で `signatures.conf` は空。これは意図的で、
何がリークしているかは使っているエージェントと MCP サーバーによって違い、
その環境を測らないと分からないから。

想定している使い方は、[AGENTS.md](AGENTS.md) を普段使っている ClaudeCode / Codex に読ませ、
診断コマンドを走らせて、自分の環境用の設定を書かせること。
提案された内容を人間が承認する。それがこのツールの形——
安全な骨組みと、エージェントが実行できる指示書。

手で設定してもいい。全部プレーンテキストで、手順は AGENTS.md にも書いてある。

## 使いはじめ

```powershell
git clone https://github.com/shoutaitou3-creator/AgentReaper.git
cd AgentReaper
powershell -ExecutionPolicy Bypass -File .\build.ps1
.\dist\AgentReaper.exe --diagnose --json
```

.NET SDK も npm も不要。ダウンロードも無い。`build.ps1` は Windows に同梱されている
C# コンパイラ（.NET Framework 4.x）を使う。全体で C# 約 3,000 行、読める量。

あとは自分のエージェントに:

> このリポジトリの AGENTS.md を読んで、このPC用に AgentReaper を設定して。

ドライランを見て承認するまで、何も終了しない。

## 安全設計

設計上の前提が特殊で、**言語モデルが・他人のPCで・プロセスを終了させる設定を書く**。
ドキュメントでお願いするのは安全機構ではない。だから制限はコードで強制していて、
**設定ファイルからは 1 つも無効化できない。**

**承認ゲート。** ドライランを見て `--approve` を実行するまで、
`dryRun = false` にしても何も終了しない。承認は `signatures.conf` のハッシュに紐づくので、
1 文字変えれば自動的に失効する。判定は `Reaper.Execute` の中にあるので、
トレイ・コマンドライン・定期走査のどの経路も通る。

**読み込み時に拒否するパターン**: 4 文字未満、
汎用語との完全一致（`node` / `python` / `chrome` / `server.js` 等）、
保護対象プロセスに当たるもの。

**走査時に無効化するパターン**: 7 種類以上の実行ファイルに当たった、
全プロセスの 15% を超えた（割合の判定はプロセス数 50 以上のときだけ）、
CPU を 60 秒以上使っているプロセスに当たった。
放置された子プロセスの CPU は実測でほぼ 0 秒。動いているものは仕事をしている。

**ツリー単位の温存条件**（1 つでも当てはまれば残す）:

- 起動中のエージェントクライアントを祖先に持つ
- そのクライアント配下で新しい方から N 個以内
- 猶予時間内（最低 5 分）
- 直近 N 回の走査で CPU 時間が増えた（最低 2 回連続の無活動を要求）
- 保護対象プロセスまたは除外 PID を含む

エディタ・端末・エージェントクライアント・OS 中核プロセスは、
設定で上書きできない保護リストに入っている。

**しきい値は搭載メモリ量から決まる。** `autoLightenFreeGb` と `warnFreeGb` は、
書かなければ搭載量から自動算出する（4% と 3%・上下限つき）。
Windows は搭載量に関わらず空きを遊ばせずスタンバイへ回すので、実空きは常に小さい
（32GB 機の平常時は実測 1.47GB）。128GB 機向けの値を 16GB 機へ持ち込むと、
平常時から常に閾値割れになり、クールダウンごとに延々と発動してファイルキャッシュを壊し続ける。
**軽くするつもりの設定で遅くなり、しかも利用者は原因に辿り着けない。**
搭載量の 25% を超える値はコードで切り詰める。

**拒否は黙って握りつぶさない。** 拒否されたものは理由つきで `--diagnose` の出力と
ログに出る。設定が黙って無効になるほうが、エラーで落ちるより危険。

試験は `tests/` にある。

### ウイルス対策ソフトについて

Defender 等に検知される可能性がある。全プロセスを列挙し、プロセスツリーを終了させ、
`NtSetSystemInformation` を呼ぶ——これは行儀の悪いソフトの挙動そのものだし、
自分でコンパイルした未署名バイナリには実績（レピュテーション）が無い。

観測される挙動としては妥当な判定で、
「大丈夫です」という他人の言葉を信じる必要はない。取れる手段は、
ソースが読める量であること、自分でコンパイルすること、
ネットワークコードが一切入っていないこと、
そして `--dry-run` で何をするか先に見られること。

除外設定を入れるかどうかは各自の判断。このプロジェクトからはお願いしない。

## コマンド

| コマンド | 内容 |
|---|---|
| `AgentReaper.exe` | タスクトレイに常駐（既定） |
| `--diagnose` | 測って報告する。何も変更しない |
| `--diagnose --json` | 同じ内容を標準出力と `dist\diagnose.json` へ JSON で |
| `--dry-run` | 1 回走査し、何が対象になるかを表示 |
| `--approve` | ドライランを確認したことを記録。回収の前提条件 |
| `--reap-once` | 1 回走査して回収（承認が必要） |
| `--lighten` | メモリリストを今すぐ解放（昇格が必要） |
| `--pool-tags` | カーネルプールをタグ単位で内訳表示 |
| `--pool-tags --attribute` | タグの所有ドライバーも逆引きする |
| `--help` | 使い方 |

`--nogui` を足すとウィンドウを出さない。出力は `last-report.txt` と標準出力に残る。

## ファイル

| ファイル | |
|---|---|
| `signatures.conf` | 回収対象の定義。既定は空。ここを自分（またはエージェント）が書く |
| `settings.conf` | 閾値と挙動。配布時は観測だけの設定 |
| `approved.conf` | `--approve` が書く。手で編集しない |
| `diagnose.json` | 直近の `--diagnose` の結果 |
| `agent-reaper.log` | 実行内容と、拒否した内容 |

## 任意のインストール

```powershell
.\install-autostart.ps1        # スタートアップにショートカット。管理者権限不要
.\install-elevated-task.ps1    # UAC 1 回。オンデマンドの昇格タスクを登録する
```

2 つめは、メモリ操作のたびに UAC が出ないようにするためのもの。
コマンドラインを固定（`--memory-commands`）したタスクを登録する。
このモードは呼び出し側から引数を受け取らず、プロセスを終了させることも無い。
承認する前に `src/Reaper.cs` の `RunMemoryCommands` を読むこと。

どちらも任意。無くても動く。

## 動作要件

Windows 10/11 x64。.NET Framework 4.x（既に入っている）。それだけ。
